# Testing and demonstration evidence

## Offline suites

From the repository root, use the existing root environment with all harness test integrations:

```sh
uv sync --locked --extra providers --extra memory --extra qdrant --extra chroma --extra faiss --extra audio
uv pip install --python .venv/bin/python -e apps/pfm
.venv/bin/pytest tests apps/pfm/tests --cov=truffles --cov=truffles_pfm --cov-report=term-missing
.venv/bin/ruff check src tests examples scripts apps/pfm
.venv/bin/ruff format --check src tests examples scripts apps/pfm
.venv/bin/python scripts/check_docs.py
```

For the standalone PFM application with its locked minimal dependency set:

```sh
uv sync --project apps/pfm --locked
uv run --project apps/pfm pytest apps/pfm/tests --cov=truffles_pfm
```

The root pytest configuration disables network sockets. The provider SDKs use strict stubbed
HTTP transports for contract tests; no real credentials are needed. PFM tests inject Truffles'
scripted chat model or an explicit application port stub. They never silently contact OpenAI.

Current combined result: **183 tests passed**, with combined statement/branch coverage rounded
to **96%**. Full logs: [test-results.txt](../artifacts/test-results.txt). One existing upstream
LangChain Community deprecation warning comes from the harness FAISS integration. This warning
does not indicate a PFM test failure.

Coverage includes exact INR arithmetic, refund caps, cross-month boundaries, duplicate conflicts,
20 concurrent retries, rollback, restart persistence, scoping, JWT algorithms/claims/permissions,
invalid model JSON, string-null regression, consent, voice errors, request/body limits, visible
fallback, category review and deterministic English/Hindi answer templates.

## Live synthetic smoke

With the loopback demo running and a configured key:

```sh
.venv/bin/python apps/pfm/scripts/live_smoke.py
```

This is an explicitly live script, excluded from pytest/CI. It makes small billed model and audio
requests through the running app's Truffles integrations. It requires a synthetic demo session.
Use a fresh demo database for each run because the fixed classification event is idempotent.
The script does not print or save credentials.

[Live evidence](../artifacts/live-results.json): six intent cases passed (summary, category,
savings, goals, Hindi and unsupported payment), one unfamiliar restaurant classification passed,
and real speech transcription and synthesis passed. The input [synthetic audio](../artifacts/voice-question.wav)
asks “How much did I spend on dining this month?”; the returned [spoken answer](../artifacts/voice-answer.mp3)
is generated by the configured provider through Truffles. No real customer data was used.

The first live run found that the model emitted `"null"` instead of JSON `null`. Strict validation
correctly fell back. A narrow optional-field normalisation and a prompt example fixed the issue;
a regression test covers it. Unknown categories, invalid months and extra keys still fail closed.

## Browser recording

[Watch the narrated MP4](../artifacts/truffles-pfm-demo.mp4). It records the actual local web app,
real API state changes and live model calls, without mocked browser routes. The narration and
sample user question are synthetic speech. The reply audio is the actual Truffles speech result.

To re-record, launch a fresh demo database and run:

```sh
.venv/bin/python -m playwright install chromium
.venv/bin/python apps/pfm/scripts/record_demo.py
```

The recording script requires `ffmpeg`, `ffprobe` and macOS `say` for its narration. The PFM
application itself does not require these tools. Browser assertions verify the visible model
mode, nudge, category, goal, Hindi response, voice result, activity trail and fallback. The
chapter manifest stores browser errors and failed HTTP response counts. No tokens or keys
appear in the video or manifest.

## Performance scope

```sh
.venv/bin/python apps/pfm/scripts/benchmark.py
```

[Local benchmark](../artifacts/benchmark.json): 1,000 known-MCC synthetic transactions produced
zero AI calls. This uses single-process in-memory SQLite; it excludes transport, disk durability,
provider inference, distributed coordination and bank integrations. It is not a production SLA.
The model timeout and concurrency controls bound failure behaviour; they are not a guarantee
of model latency or availability.

## Not tested against real bank systems

No real CBS/event bus, bank SSO, bank database, external customer notifications, real microphone
hardware permission flow, or actual self-hosted model has been validated. Audio-file input,
live transcription and playback are exercised. Browser microphone code shares that audio path,
but device-specific recording requires a bank's supported-device acceptance tests.

## Standalone and container verification

The independent `apps/pfm/.venv` created from its own lockfile passed **65 PFM tests**, with
**92.09%** combined statement/branch coverage at that run. See
[standalone log](../artifacts/pfm-standalone-tests.txt). This confirms the PFM app does not rely
on the many optional vector-store/provider packages in the root development environment.

The Docker image built successfully and passed: non-root UID 10001, read-only root filesystem,
synthetic seeded dashboard, local-fallback chat, and refusal to start bank mode without the
required identity verifier. Logs: [build](../artifacts/container-build.txt),
[smoke result](../artifacts/container-smoke.json). The test container was removed afterwards;
the local image remains available as `truffles-pfm:local`.

For a quick credential-free scripted demonstration:

```sh
uv run --project apps/pfm python apps/pfm/scripts/offline_demo.py
```

This asserts categorisation, budget nudging, duplicate protection and a correct summary. Its
fallback mode is explicit and its model call count must remain zero.


The final video is 119.2 seconds, 1440×1000 H.264 with AAC narration, the real live speech
reply, selectable English narration captions and chapter markers. It was decoded end-to-end,
its audio level checked, and representative opening/voice/final frames inspected. The browser
recording manifest reports zero JavaScript errors and zero failed HTTP responses.

An additional browser check posted an event through the API while the page was already open.
Its category, ledger change and budget nudge appeared automatically on the next 10-second
refresh, without a customer interaction. See [automatic event evidence](../artifacts/automatic-event-browser.json).
